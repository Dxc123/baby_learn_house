# 2C 共用阅读器与首批文学内容设计

日期：2026-10-20。状态：用户确认计划后已实施；当前能力与验收边界见 docs/phase-2c-status.md。

## 目标与既有约束

延续网页版复刻路线，为儿童和陪读家长开放“学习古诗词、成语故事、三字经”三个现有入口。验收结果是：离线选择作品、逐句看注音与解释、听单句或连续朗读、恢复阅读位置、手动标记学会。

用户已要求继续下一阶段；范围沿用已存在的第二阶段路线图：10 首古诗、10 则成语故事、三字经开篇 12 个三字句。以下作品清单、进度粒度及错误策略为本次设计默认值，供本文件审阅时调整。

保留 Flutter 3.41.6 / Dart 3.11.4、GetX、Android/iOS、本地资源和 `learning_state_v1`。原有 209 个学习 ID、设置、课程顺序、字形及字帖功能保持兼容。不新增账号、云同步、在线 TTS、视频、插图生成、背诵评分或自动判定学会。

## 方案选择

推荐在现有学习条目上增加可选阅读正文，由一个阅读器渲染三类内容。保留现有目录、搜索和已学筛选，增加阅读器与可取消朗读队列；不把文学正文塞入单字 `text/pinyin` 字段。

替代方案一：三个入口分别做详情页。首版容易开始，但注音、连续播放、生命周期与错误处理会重复，后续修复容易不一致。

替代方案二：内嵌网页阅读器。能复用网页样式，但增加离线资源、原生音频通信、字体缩放和读屏适配成本，也难以延续现有原生交互。

因此选择原生共用阅读器，不迁移状态管理，不引入新的页面或音频框架。

## 首批内容与计数

### 古诗，10 个学习条目

固定候选清单：咏鹅、静夜思、春晓、悯农（其二）、登鹳雀楼、寻隐者不遇、江雪、古朗月行（节选）、小池、山行。

《古朗月行》仅取“小时不识月”起的前四个五言句，标题明确标“节选”。《悯农》明确第二首，避免同名混淆。实施时逐篇核对古籍正文版本、作者及出处，保留来源 URL 和版本说明；解释为自编儿童语言，不复制现代网站译文、注音或配图。任何篇目正文未核实前不得生成音频或标为已校对。

### 成语故事，10 个学习条目

固定十篇为：守株待兔、亡羊补牢、画蛇添足、掩耳盗铃、井底之蛙、刻舟求剑、拔苗助长、狐假虎威、自相矛盾、愚公移山。

每篇自编 4–6 句短故事、每句 12–28 个汉字，另有一条不绝对化的启发说明。页面标注“根据传统故事改写”，核实典故出处，不将现代改写冒充古籍原文；正文不复制原站内容。

### 三字经，12 个学习条目、36 字

固定范围：人之初、性本善、性相近、习相远、苟不教、性乃迁、教之道、贵以专、昔孟母、择邻处、子不学、断机杼。

12 个三字句各保留独立学习 ID，阅读页将它们组合为“开篇 12 句”一篇。每句有注音与儿童解释；整篇说明这些是传统蒙学文本中的观念，使用适龄、尊重儿童差异的解释，不把传统判断当成对孩子的标签。

新增 32 个学习条目，最终总数 241，开放入口从 13 增至 16。播放行不额外计入首页分母；连续播放不跨越到下一篇作品。

## 数据结构与兼容

新增 `ContentKind.reading`，三个类别 ID 沿用 `poetry`、`idioms`、`classics`。扩展 `LearningItem` 的可选字段 `readingId`，旧 JSON 缺失时为 null；既有 `text` 用作目录标题，`pinyin` 是标题的逐字注音。正文单独放入 `assets/data/readings.json`，按需加载，单篇失败不能影响拼音、认知或汉字启动。

`ReadingPassage`：稳定 id、categoryId、title、titlePinyin、author/sourceLabel、intro、lines、provenance。`ReadingLine`：稳定 id、text、与正文字符一一对应的 pinyin、explanation、audio、audioQuality、可选 learningItemId。

正文汉字及标点采用 Unicode 字符序列对齐；标点位置的注音为空字符串，汉字位置必须有非空注音。标点依附前一个字显示，不单独跑到下一行；文本与注音作为整体单位换行。标题与正文都遵守全局拼音开关，解释默认不加注音。

诗与故事条目 ID 使用 `poetry-<slug>`、`idiom-<slug>`；正文行使用 `<passageId>-line-01` 等语义稳定 ID，修改排版不改变 ID。三字经条目为 `classic-opening-01` 至 `classic-opening-12`，共享 readingId `classics-opening`，正文行分别关联相应学习条目。

课程生成器加入规范源 `tool/content_sources/readings.json`，同一次构建确定性地产出目录与阅读正文。先验证两份结果及交叉引用，再写临时文件、备份旧内容并替换；写入抛错时恢复两份原文件，生产生成器不读取测试 fixture。两份文件附带相同 readingRevision，App 按需加载正文时校验版本；意外断电造成不一致时仅禁用阅读并提示重试，不破坏既有 209 项学习。`--check` 对两份文件只比较、不写入。正文校验包含重复 ID、类别/条目引用、空文本、注音错位、非法音频路径及缺失解释。

## 阅读流程与进度

首页进入现有类别列表；古诗/成语点击条目进入 `/read/:readingId`，三字经条目携带 `line=<stableLineId>` 定位对应句。非法作品或句参数显示可返回的错误/回退提示，不根据当前排序的索引定位。

阅读页包含标题、作者或来源、自编解释说明、逐句正文、单句播放、当前句高亮、“上一句/下一句”“从当前句连续朗读/停止”以及手动“我已学会”。文字使用可滚动布局，内容最大宽度沿用现有阅读舒适范围；大字号不固定行高、不横向溢出。自动定位当前句，且不因用户滚动反复抢回位置。

诗与故事按整篇标记学会；三字经按当前三字句标记。听完或读到末尾均不自动标记。古诗和故事末句的下一句按钮显示“本篇已读完”，不自动跳到下一篇。

持久化继续使用现有 `learned` 和 `cursors` map，无强制迁移：类别 cursor 仍保存学习条目 ID；额外键 `reader:<passageId>` 保存正文行 ID。进入作品、手动切句时保存位置；音频逐句完成不触发大量持久化写入。失效行 ID 回退第一句；写入失败提示但允许继续离线阅读。三字经每次选句同时更新类别 cursor 对应三字句条目。

## 单一音频所有权与可取消队列

现有 `LearningAudio` 是唯一音频所有者。扩展它的串行命令队列以支持按句播放，阅读器不创建第二个底层播放器，也不直接订阅后端并绕过取消逻辑。

连续朗读从当前句到本篇末句；只在当前播放会话的正常 completion 事件到达后前进，不能用固定时长定时器切句。单句播放、停止、切页、应用后台、页面销毁、其他学习页点播均先使旧会话 token 失效，再停止旧声音；任何旧异步回调不能启动下一句。

每次播放记录会话/请求身份，当前行高亮通过受控回调更新；已被取消的会话及旧 completion 不更新高亮、不推进队列。底层适配若不能给 completion 附带播放身份，必须通过播放实例隔离或解绑旧实例事件实现，不能假定“加一个 token”便能识别所有迟到事件。

遇到缺录音的句子时，停止连续朗读并定位该句，显示“本句暂缺录音，可继续阅读”；不静默跳句，不伪称全篇播放完成。解码或加载失败时停止队列并显示重试；用户重试从当前句开始。每篇末句完成后清除播放态，保留当前阅读位置。

首版允许随包合成示范，统一标记 demo，页面说明“离线合成示范 · 未经教学听审”。仅为已完成正文和逐字注音核对的句子生成；听审未通过或没有可用资源的句子保留 unavailable。新增音频存入独立 reading 子目录及来源清单，校验 PCM、非静音、文件存在和文本来源。既有 98 段示范及 111 项暂缺录音的状态不变。

## 测试、验收与交付

1. 数据：32 个新增学习条目、21 篇正文（诗 10、故事 10、三字经合集 1）；所有旧 209 ID 保留，总数 241、开放入口 16。三字经严格 12 行、每行 3 字，共 36 字，不把三字句拆成 12 篇重复正文。
2. 资源：正文、注音和录音清单对应；无录音/损坏文件明确失败；重建与 --check 无漂移；生成失败保留既有可用文件。
3. 队列：正常完成顺序、末句停止、连续重启、单句抢占、切页/后台取消、迟到完成事件、异步 stop/play 竞态、失败后重试、缺录音不跳句。使用可控假后端，覆盖当前单条播放回归。
4. UI：320px、200% 字号、平板、关闭拼音、长句标点、末句行为、非法路由、手动标记及恢复位置；阅读操作不得影响汉字描红/字帖状态。
5. 工程：格式化、Python 生成器测试、Dart 内容资源审计、静态分析、全套 Flutter 测试、Android debug 和 iOS simulator 构建。iOS 走通选篇→点句→连续朗读→停止→返回→恢复；Android 若仍没有 AVD，则明确保留设备验收缺口，不安装私人真机。
6. 内容质量：正文核对、结构校验、合成录音与专业教学听审分别记录。交付文档和截图不得将 demo 标作标准专业录音，不宣称全站已经复刻完成。

## 设计自查

范围已限制为一个阅读子系统；三类内容共用正文模型、播放所有者和进度存储。主要风险是迟到音频事件、跨类别取消、标点注音错位、三字经计数和旧存储兼容，上述均有明确行为与验收点。Android 原生 PDF 的上批次设备补验独立保留，不把它作为阅读器实施的前置阻塞。
